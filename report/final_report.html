1. Problem Definition & Application

This project studies whether interpretable trajectory statistics can identify high-quality robot demonstrations at scale. The task is framed as a binary classification problem at the episode level: given one full robot trajectory, predict whether that demonstration should be considered high quality or low quality.

The real-world importance is practical. Large robot imitation-learning datasets often contain demonstrations with inconsistent smoothness, unnecessary corrections, long detours, or inefficient execution. If we can detect high-quality demonstrations using simple kinematic features, then data filtering becomes cheaper, more interpretable, and easier to scale than relying only on manual inspection or expensive policy training loops.

This is useful for robot learning pipelines in manipulation, warehouse automation, and human-robot collaboration, where better demonstrations can improve downstream policy performance while reducing annotation and compute cost.

2. Dataset & Features

Dataset Summary

We use 8 LeRobot datasets from HuggingFace: 5 simulation datasets and 3 real robot datasets. The raw merged table contains 251,802 frame rows and 7 original columns.

After episode aggregation, the modeling table contains 5,026 episodes with engineered trajectory-level features.

Input Variables and Target

Raw frame-level variables: `source`, `episode_index`, `frame_index`, `observation_state`, `action`, `next_reward`, `next_done`.

Engineered input features: 32 episode-level motion features derived from state/action sequences.

  • Smoothness: jerk, action difference statistics
  • Efficiency: path efficiency, total path length, episode length
  • Consistency: action variance, correction count
  • Stability/diversity: final stability, state diversity, net change

Target variable: binary demonstration quality label.

  • Simulation: high quality if episode max reward is above that dataset's median.
  • Real robot: high quality if episode length is below that dataset's median, because reward is saturated at 1.0.

3. Methodology & Analysis

The full workflow follows a big-data pipeline using PySpark DataFrames for scalable processing. The main steps are:

StepWhat We DidWhy It Matters
Data loading Merged 8 LeRobot datasets into one frame-level parquet table. Creates a unified analysis dataset across simulation and real environments.
Preprocessing Checked missing values, standardized schema, and used relative paths/parquet storage. Ensures reliable downstream feature computation.
L2 norm conversion Converted variable-length state and action vectors into magnitude-based features. Makes datasets with different state/action dimensions comparable.
Episode aggregation Grouped frame rows into episode rows using PySpark. The prediction target is trajectory quality, not frame quality.
Feature engineering Computed 32 interpretable kinematic features such as smoothness, path efficiency, correction count, and final stability. Encodes motion quality without needing deep sequence models.
Evaluation design Compared models separately on simulation and real-robot subsets using cross-validation metrics. Avoids mixing two environments with different label semantics.

A key methodological choice is interpretability. Instead of directly feeding raw trajectories into a large neural model, we summarize each demonstration using motion statistics that can be explained to humans. This aligns with the research question: not just whether quality can be predicted, but whether it can be predicted using features that are understandable and actionable.

4. Models

We implemented multiple models and report at least two PySpark MLlib classifiers, satisfying the course requirement. The primary models are Decision Tree, Random Forest, and Gradient Boosted Trees (GBT). We also kept an MLP as an optional deep-learning baseline.

ModelFrameworkWhy Selected
Decision Tree PySpark MLlib Highly interpretable baseline and easy to explain in terms of feature splits.
Random Forest PySpark MLlib Robust ensemble model that usually performs well on tabular features and reduces overfitting.
GBT PySpark MLlib Captures nonlinear relationships and often delivers stronger accuracy on structured tabular data.
MLP (optional baseline) PyTorch Included as a comparison to test whether a neural baseline can outperform tree-based methods.

The model comparison shows a clear pattern. Tree-based models outperform the MLP baseline on simulation data, and GBT achieves the best overall performance in both settings. Real-robot quality is much easier to predict than simulation quality, suggesting that efficiency-based quality signals are more strongly reflected in trajectory statistics.

6. Insights

  • Interpretable trajectory features work. Even simple motion statistics can identify high-quality demonstrations with strong performance, especially on real robot data.
  • Quality is environment-dependent. Simulation data is harder because reward-based labels are noisier and less directly tied to motion patterns than efficiency-based labels.
  • GBT is the strongest practical choice. It balances nonlinear modeling power with good performance on tabular engineered features.
  • Feature importance is meaningful. Smoothness, action magnitude patterns, and temporal consistency repeatedly appear among the most informative predictors.
  • Practical implication: Demonstration filtering can be done before expensive policy training, which may improve data efficiency in large-scale robot learning pipelines.
